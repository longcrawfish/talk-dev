# song gift 规划建议（第 2 轮）

针对 `docs/song/song-gift-plan.md` 的评审建议，按优先级排列。重点在成本/风控和架构缺口。

---

## 一、成本与风控（最关键）

### 1. AI 音乐生成的成本承担问题
当前流程是「生成两个版本 → 预览 50s → 解锁才扣积分」。如果用户反复生成却不解锁，或两版都不满意后免费重生成，API 成本全由站点承担，存在明显亏损/被薅风险。

建议：
- 生成音乐这一步就**冻结/预扣积分**，或
- 限制免费重生成次数（如重生成需扣少量积分）。

### 2. 音乐生成模型选型
Replicate 上的音乐模型（MusicGen、Stable Audio 等）质量和「带人声歌词」能力，可能不如 Suno/Udio 这类专门做歌曲的服务。

建议：先做选型 POC，确认能生成「带词人声歌曲」，这直接决定产品可行性——这点不验证，整个 AI 工具线都悬。

### 3. 内容合规
用户输入的故事/歌词、上传的封面图都需要审核（NSFW、版权歌词、诽谤）。各 AI 音乐平台对商用、翻唱有不同政策，需在 Terms 里明确版权归属和商用范围。

---

## 二、架构缺口

### 4. Next.js on Workers
需用 `@opennextjs/cloudflare` 适配，部分 Node API/中间件不兼容。建议先验证 Google 登录、Creem 支付回调等关键依赖能跑通再全面动手。

### 5. 异步任务机制没写（关键缺口）
音乐生成要 3~5 分钟，Workers 有执行时长限制，不能在请求内同步等待。

建议：
- 用 **Workers Queues + D1 任务表**，
- 前端轮询/长连接查状态，
- 完成后写 R2 并邮件 + 站内通知。

文档只提到「悬浮窗让用户看到运作」，后台执行机制是空白，必须补上。

### 6. D1 并发写
D1 是 SQLite，积分扣减、草稿写入是高频写。积分余额等关键数据要用**事务 + 乐观锁**，避免并发超扣。

### 7. 音频分发
R2 + Workers 需开启 Range 请求/流式播放；50s 预览建议单独裁剪片段，避免完整文件被轻易抓取下载。

---

## 三、流程与产品

### 8. 「返回现场」机制
登录、支付完成后要回到原步骤，建议统一用 `draftId` 承载状态，登录/支付回调都带 `draftId` 回跳，实现可靠的会话恢复。

### 9. 免费工具链接生成限流
free-gift-maker 免登录，需做 IP/频率限制防刷量。

### 10. 草稿过期与进行中生成的竞态
24h 过期删除资源前，要先检查是否有未完成的生成任务，避免删了文件但任务还在写 R2。

### 11. 收礼页下载
音频/歌词 PDF 考虑加水印或署名，并标注 AI 生成 + 版权声明。

---

## 四、经济模型

### 12. 缺单位经济性测算
n、m 待定可以，但应先算出「单次音乐生成的成本（API + 存储 + 流量）」作为积分定价基准，否则赠送额度可能亏损。建议文档补一张 unit economics 表。

### 13. 每日登录送积分
易被多账号薅，需结合设备指纹/风控。

---

## 五、缺失模块

### 14. 基础设施
- 数据分析：Plausible / PostHog
- 错误监控：Sentry
- **邮件通知**：生成完成提醒（比站内更可靠，异步场景必备）

### 15. i18n
既然支持多语种音乐，站点本身做多语言对 SEO 和转化都有好处。

### 16. 法律页
- Terms：明确 AI 生成内容的版权归属
- Privacy：符合 GDPR

---

## 六、优先行动项

建议优先做两件事确认可行性：

1. **音乐生成模型选型 POC**（能否生成带词人声歌曲、质量/成本如何）
2. **单次生成的成本测算**（API + 存储 + 流量，作为积分定价基准）

这两点直接决定整个商业模式站不站得住。

# 修订版方案（song gift）

> 在原方案 `song-gift-plan.md` 基础上，整合上述建议形成。主题：数字音乐（礼物）定制。

## 技术架构

- 前端：Next.js（经 `@opennextjs/cloudflare` 部署到 Cloudflare Workers）
- 数据库：Cloudflare D1（SQLite）
- 文件存储：Cloudflare R2
- 网站部署：Cloudflare Workers
- **异步任务：Cloudflare Workers Queues + D1 任务表**（音乐/图片生成为长耗时任务，不在请求内同步等待）
- 账户登录：Google OAuth
- 支付：Creem
- AI Model API：
  - 歌词/文本生成：OpenRouter
  - 音乐生成：Replicate（MusicGen / Stable Audio 等）或备选 Suno/Udio 官方 API —— **选型待 POC 验证**
  - 图片生成（封面）：Replicate
- 音频分发：R2 + Workers，开启 Range 请求/流式播放；预览片段单独裁剪
- 基础设施：
  - 分析：Plausible / PostHog
  - 错误监控：Sentry
  - 邮件服务：用于音乐生成完成等异步通知

**POC 待验证项（开发前必须确认）：**
1. Next.js on Workers 对 Google 登录、Creem 支付回调等关键依赖的兼容性。
2. 音乐生成模型能否稳定产出「带词人声歌曲」，以及单次成本与质量。

## 网站结构

```
网站首页
	|
	|（tools）
		|- free-gift-maker （完全免费、免登录）
		|- AI-song-maker （消费积分）
		|- mixed-gift-maker （上面两个的混合版）
	|
	|- `/gift/[id]` 用户收礼页面
	|
	|（用户个人中心）
		|（创作草稿模块：未完成、待支付的创作）
		|（创作完成的作品记录）
		|（积分、支付记录）
		|（其它必要的个人中心模块）
	|
	|（支付相关：结算/支付、价格页/套餐页）
	|
	|（场景页，多语言）
		|- Birthday / Anniversary / Christmas
		|- Friendship / Congratulations / Mother's Day
		|- ……
	|
	|- 联系页（用户反馈）
	|- 后台管理员页面（礼物相关统计数据）
	|- 法律页：Terms（AI 生成内容版权归属与商用范围）、Privacy（GDPR）
	|- 其它页面（关于页等）
```

新增说明：
- 后台管理员页面需做角色/权限隔离，与普通用户数据严格分离。
- 站点本身做 **i18n 多语言**（与多语种音乐生成呼应），利于 SEO 与转化。

### tools 业务流程（通用规范）
- 三款工具参照 digiflower.net 的「Bouquet Builder」体验：步骤切换在当前页内完成，不跳转，逐步引导。
- 三款工具做成**可复用的独立模块**，在不同工具页引入。
- 所有需要登录/支付的环节统一用 `draftId` 承载现场状态，登录与支付回调都带 `draftId` 回跳，实现可靠「返回现场」。

### 1. free-gift-maker
免费、免登录。

操作步骤：
```
选场景（必选） -- 选择固定音乐 -- 填写卡片（接收者名字、信息、发送者名字） -- 生成链接以及二维码
```
其中「选择音乐」与「填写卡片」至少操作一个。

- 音乐素材：采集可商用音乐（来源 pixabay），存放于 R2；按场景配置，每场景 2~3 首。
- **风控：** 链接生成免登录，需做 IP/频率限流，防刷量。

### 2. AI-song-maker
使用 AI 大模型创作音乐、歌词、封面图。

操作步骤：
```
选场景（必选） -- 选择音乐风格 -- 选择语言（英/法/西...） -- 选择声音（男/女/系统自选）
-- 填写故事/想法（接收者名字、故事等） -- [登录校验] -- [草稿数量校验]
-- 生成歌词、预览（可编辑、可重新生成） -- 生成音乐（两版本，异步）-- 预览，二选一解锁
-- 选择封面（上传 / AI 生成 / 默认） -- 填写贺卡（可选） -- 生成分享链接
```

关键修订点：

1. **登录校验**：「填写故事/想法」完成后进入下一步前检查登录；未登录则弹窗，登录后凭 `draftId` 返回现场继续。
2. **草稿数量校验**：生成歌词前检查草稿记录，24 小时内超过 9 条则提示去「个人中心 > 创作草稿模块」处理，并给站内跳转链接。
3. **草稿记录**：歌词生成后即写一条草稿，后续每步在该草稿中记录；创作完毕生成分享链接后移除草稿，并存一条完成记录。
4. **内容审核**：用户输入的故事/歌词、上传的封面图需过审核（NSFW、版权歌词、诽谤等），违规拦截并提示。
5. **生成音乐（异步）**：
   - 调用 API 走 **Workers Queues + D1 任务表**，不在请求内等待。
   - **生成前冻结/预扣积分**（解决成本承担问题）；任务失败则退还。
   - 界面悬浮窗展示进度；等待期间用户可继续「选择封面、填写贺卡」。
   - 提示用户预计等待 3~5 分钟，完成后**邮件 + 站内通知**，并可在草稿模块预览。
   - 生成的音乐/图片存放于 R2。
6. **预览与解锁**：
   - 听 50s 预览（完整音乐不低于 2min；预览片段单独裁剪，防完整文件被抓取）。
   - 二选一解锁 → 扣积分 → 生成分享链接；积分不足跳价格页，支付后凭 `draftId` 返回现场。
7. **重新生成**：两版都不满意可重新生成，但**需扣少量积分**（避免无限免费重生成造成成本流失）。弹窗让用户修改之前的编辑内容后重新生成。

### 3. mixed-gift-maker
混合版：
```
1. 选场景（必选） -- 2. 选择音乐
```
第 2 步提供「固定音乐」与「personalized song gift」两个选项：

- 选「固定音乐」→ 进入 free-gift-maker 后续步骤（3. 填写卡片 → 4. 生成链接与二维码），免费、免登录。
- 选「personalized song gift」→ 进入 AI-song-maker 后续步骤（风格 → 语言 → 声音 → 故事 → 歌词 → 音乐 → … → 分享链接），特定步骤需登录与支付。

## 用户个人中心

登录后才能查看，且只能看本账号数据。

**创作草稿模块：**
- 仅 AI 流程的草稿才记录；free-gift-maker 草稿服务端不保存。
- 每条草稿可继续编辑、继续支付积分；继续编辑的工具体验与 AI-song-maker 一致（复用组件）。
- 仅保存 24 小时内的草稿，上限 10 条，页面需给出提示。
- **过期删除前的竞态处理：** 删除资源（及关联 R2 文件）前，必须先检查是否有未完成的生成任务；若有则跳过或先终止任务，避免删了文件而任务还在写。
- 达到/超过 10 条上限，提醒用户完成创作或删除部分记录。

## 用户收礼页面 `/gift/[id]`

- 设计精美、交互顺畅，给收礼人惊喜感与仪式感；**移动端优先**。
- 音乐播放器：缩小版（横幅）与放大版（全屏播放界面）切换。
- 提供下载：音频文件、歌词文件（PDF，带署名/水印与 AI 生成 + 版权声明）。
- 提供「回礼 / 制作音乐」按钮，形成传播闭环。

## 经济模型

除免费功能外，所有消耗以积分结算，主要覆盖 AI 工具成本。

**积分来源：**
- 新用户赠送
- 每日登录赠送
- 付费购买

**积分有效期：**
- 赠送积分（新用户/每日登录）：30 天
- 付费购买积分：180 天

**使用规则：** 优先消耗有效期最短的积分（FIFO）。

**关键修订：**

1. **单位经济性测算（unit economics，开发前必须完成）：**
   - 单次音乐生成成本 = API 调用 + R2 存储 + 流量 + 重生成概率摊销。
   - 以此作为积分定价与赠送额度的基准，避免亏损。建议在文档附测算表。
2. **成本前置**：生成音乐时预扣积分（见 AI-song-maker 流程），解锁时不重复扣；预览/重生成按规则计费。
3. **反薅羊毛**：每日登录赠送需结合设备指纹/风控，防多账号刷量。
4. **新用户/每日登录阶梯式赠送**（用于冷启动推广）：
   - 前 1k 新用户每人赠 3n，第 2 个 1k 赠 2n，第 3 个 1k 赠 n，其后递减。
   - 上线后第 1 个 90 天每日登录赠 3m，第 2 个 90 天赠 2m，第 3 个 90 天赠 m，其后递减。
   - （n、m 数值待定，以单位经济性测算为依据确定。）

## 推广营销

1. **工具站引流**：本人其它工具站在主题相关页面加 song gift 链接导流，推进冷启动。
2. **用户传播**：
   - free-gift-maker 免登录，降低使用门槛。
   - 前期加大新用户与每日登录的赠送额度（见经济模型阶梯式赠送），让用户用得爽、多传播。
3. **外链建设**：
   - 免费外链：ProductHunt、IndieHackers 等。
   - 付费外链：theresanaiforthat.com、toolify.ai、creati.ai 等 AI 目录站。

## 优先行动项（落地顺序）

1. **音乐生成模型选型 POC**：能否生成带词人声歌曲、质量与单次成本。
2. **单次生成成本测算**：形成 unit economics 表，作为积分定价与赠送额度基准。
3. **Next.js on Workers 兼容性 POC**：验证 Google 登录、Creem 回调等关键依赖。
4. 完成上述三项后再进入正式开发。
