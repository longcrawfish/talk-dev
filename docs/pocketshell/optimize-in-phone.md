# PocketShell 手机墨水屏显示优化

适用环境：Bigme HiBreak S Color、Brave Nightly、`https://pshell.taloseng.com`。

记录日期：2026-10-17。PocketShell 部署见 [readme.md](./readme.md)。本文提供操作步骤，不代表设置已应用或已在该手机上验收。上游设置源码已核实；Brave Nightly 与 Bigme 固件的实际菜单可能不同，下文不假定固定菜单路径。

## 目标与调整顺序

当前反馈：终端对话字号偏小，部分文字受背景色块影响；底部按钮和设置菜单有模糊感。

按以下顺序调整，每次只改变一项，并在同一段文字上比较：

1. PocketShell 字号调到 18，切换浅色主题。
2. 调整手机刷新模式，检查模糊是否来自残影。
3. 试用本文的高对比主题，检查文字与色块。
4. 必要时使用浏览器页面缩放改善菜单大小。
5. 仍有局部色块问题时，调整终端内工具自身的配色。

建议先记录原主题、字号、浏览器缩放和设备显示参数，方便恢复。不需要修改 Caddy、域名、HTTPS 或重新配对。

## 1. 放大终端字号

在手机打开 PocketShell 的设置，找到字号滑块，先调到 **18**。

已查阅的上游设置代码中，范围为 10–18，步长为 0.5。安装版本如果显示不同范围，以实际界面为准。字号变大后终端每行可容纳的字符会减少，换行增多属于正常现象。

在等宽字体选项中，可以对比 JetBrains Mono 与默认 Maple Mono。使用同一段英文、数字和代码判断哪种更易辨认，不预设某种字体在本机一定更清晰。中文通常回退到系统字体，因此切换等宽字体对中文的影响可能有限。

注意：设置页里一些说明文字使用独立的小字号。终端字号变大，并不代表底部导航、设置说明也会同步放大。

## 2. 先建立浅色显示基线

1. 在 PocketShell 设置中选择 **奶油浅 / Cream Light**。
2. 如果浏览器或设备启用了强制深色、颜色反转等功能，先关闭对应功能，避免对网页再次转换颜色。
3. 暂时保持浏览器页面缩放为 100%，观察终端正文、输入区域、按钮和设置说明。
4. 切换主题后做一次设备全屏刷新，再判断是否清晰。

浅色主题是初始对照，不保证其暖色背景、灰色说明文字在彩色墨水屏上都有足够对比。如果仍有问题，继续使用下面的自定义主题。

## 3. 调整 Bigme 的显示与刷新设置

以下是实机调节建议，具体入口和选项名称取决于固件；只调整设备实际提供的选项。如果支持按应用保存设置，优先只针对 Brave Nightly 配置。

| 调整项 | 起始建议 | 观察重点 |
| --- | --- | --- |
| 刷新模式 | 优先尝试偏清晰、阅读或质量的模式，而非最快模式 | 静止文字的笔画是否更完整；同时检查输入延迟 |
| 全屏刷新 | 主题切换或出现明显残影后手动触发一次 | 刷新后改善明显，说明残影是影响因素之一 |
| 黑色增强 / 对比度 | 如果提供此选项，从低档逐步增加 | 小字变深即可，避免汉字笔画粘连或背景块变黑 |
| 背景净化 / 浅色过滤 | 如果提供此选项，谨慎小幅调整 | 不要把灰色说明、细边框和选中状态一起过滤掉 |
| 前光 | 按环境光调整到舒适且能看清细字 | 不把提高亮度当作字号或配色的替代方案 |

区分两种现象：全屏刷新后恢复清晰、滚动后又模糊，优先调刷新模式；刷新后仍看不清相同的字和背景，优先调字号及配色。

## 4. 导入高对比浅色主题

PocketShell 支持在设置中粘贴导入 `.ghostty` 配色。下面是针对当前问题准备的**试用配置**，采用白底、黑色正文和较深的彩色文字，不是已通过该设备验收的主题。

操作步骤：

1. 打开 PocketShell 设置中的主题区域。
2. 展开自定义主题导入入口。
3. 名称填写 `E-Ink High Contrast`。
4. 将下面完整内容粘贴到主题文本框，提交导入。
5. 从主题列表选中该主题，返回终端并做一次设备全屏刷新。

```ini
# ps-accent = #222222

background = ffffff
foreground = 000000
cursor-color = 000000
cursor-text = ffffff
selection-background = 222222
selection-foreground = ffffff

palette = 0=000000
palette = 1=800000
palette = 2=005000
palette = 3=604000
palette = 4=000080
palette = 5=600060
palette = 6=005050
palette = 7=dddddd
palette = 8=444444
palette = 9=900000
palette = 10=006000
palette = 11=705000
palette = 12=000090
palette = 13=700070
palette = 14=006060
palette = 15=ffffff
```

这里保留亮色和暗色槽位，因为终端程序可能同时用它们绘制文字和背景。不要把 16 色全部改成黑色，否则反色文本或有底色的区域可能完全无法辨认。

配置的作用与限制：

- 白底黑字改善默认终端正文；深色彩色槽位用于降低浅色彩字难辨的问题。
- 应用会从主题生成界面颜色；主题本身不能直接指定所有按钮字号、字重，也不保证所有界面都变为纯黑白。
- ANSI 调色板既可能用于文字，也可能用于背景。某些终端工具的色块仍可能产生低对比，需要单独调整该工具。
- 工具直接输出的 RGB 真彩色或其他颜色索引不一定跟随这 16 个槽位改变。
- 成功、警告、错误不能只靠颜色识别，阅读时仍要看对应文字或符号。

如果导入入口不存在，先使用内置浅色主题，不要清空站点数据。可以核对实际安装版本与上游功能差异后再决定是否升级。

## 5. 放大底部按钮、设置菜单等界面文字

终端字号和界面字号是两套设置。已查阅的 `SettingsPanel.svelte` 中，设置标签为 13px，说明文字为 10.5px，还有部分 9–12px 的文字。因此，把终端字号调到 18 或导入主题，并不会同步放大这些文字。下面的字号是建议目标，尚未在手机上验收。

| 区域 | 建议起点 |
| --- | --- |
| 底部按钮文字、菜单选项、设置标签 | 16px |
| 设置说明、辅助提示、数值 | 14px |
| 设置分组标题 | 18px |
| 触摸按钮高度 | 至少 44px，并根据文字换行增高 |

### 5.1 先用浏览器缩放，无需重新部署

先完成 PocketShell 终端字号调整，再试浏览器缩放，避免同时改变多个变量。

1. 在 Brave Nightly 的普通浏览器标签页打开 `https://pshell.taloseng.com`，方便访问浏览器菜单；如果平时使用桌面 PWA 图标，稍后再单独验证该入口。
2. 打开浏览器菜单，查找“页面缩放 / Page Zoom”。若没有，在设置中查找“无障碍 / Accessibility”以及缩放相关选项。不同 Nightly 版本入口和功能可能不同，以实际界面为准。
3. 记录原值，从 **110%** 开始，再试 **125%**。如果支持按站点保存，仅作用于 `pshell.taloseng.com`；若只有全局默认缩放，注意它会影响其他网站。
4. 返回页面，分别打开底部按钮区和设置菜单。检查中文标签、说明文字、字号滑块旁的数值是否更容易辨认。
5. 检查底部按钮是否完整、设置内容是否可滚动、输入框是否被键盘遮挡、终端最右侧是否被裁切；再测试横竖屏切换和键盘展开、收起。
6. 关闭并重新打开页面，确认缩放仍有效。若使用 PWA，再从桌面图标进入验证，不假定浏览器标签页的缩放一定同步到 PWA。
7. 如果出现布局问题，退回上一级缩放，必要时恢复到 **100%**，保留 PocketShell 自己的字号 18。

125% 是试验值，不等于所有文字都已达到上表的字号。例如，10.5px 按比例放大 1.25 倍仍只有约 13.1px。若底部已经拥挤、设置说明仍然偏小，应采用第 5.3 节的前端修改方式。

“文本缩放”和“页面缩放”不完全相同。文本缩放可能只改变网页文字，对 Canvas/WebGL 绘制的终端无效；页面缩放也需要实测终端重排是否正常。不要把双指临时放大当成已解决整体布局。

### 5.2 浏览器没有合适选项时，尝试系统显示设置

1. 记录手机原有的字体大小和显示大小。
2. 在 Android 系统设置中搜索“字体大小”或“显示大小”，先只增大一档字体大小，返回 PocketShell 检查。
3. 若网页按钮文字没有变化，恢复字体大小，再单独尝试增大一档显示大小。
4. 重复第 5.1 节中的布局检查；不合适就恢复原值。

系统设置可能影响其他应用，也不保证改变网页固定字号或终端字号。它适合作为备选试验，不作为已经解决菜单大小问题的依据。

如果有“桌面版网站”选项，保持关闭。若怀疑 Nightly 存在渲染问题，可用稳定版 Brave 对同一页面做对照；新浏览器可能需要重新配对。不要为了试验先清除 Nightly 的站点数据，以免丢失当前设备身份和本地偏好。

### 5.3 长期方案：修改 PocketShell 前端界面字号

这一方案需要修改源码、构建和部署，不是把 CSS 粘贴到主题导入框。当前 `talk-dev` 工作区只有部署与优化文档，安装目录 `/opt/pocketshell` 中是 Agent 二进制；本次没有修改运行中的应用。

实施步骤：

1. 记录实际运行的 Agent 版本、服务启动路径和启动参数，保存原二进制。先取得与部署版本对应的 PocketShell 源码，避免直接使用变化中的 `main` 覆盖现有版本。
2. 在源码根目录查找界面字号及底部工具栏组件：

   ```bash
   rg -n 'font-size|fontSize' app/src
   rg -n 'toolbar|bottom|navigation' app/src
   ```

3. 从 `app/src/components/SettingsPanel.svelte` 开始，按上表调整标签、说明、数值、选项和分组标题。找到底部按钮的实际组件后，再调整对应样式；不要只改 `body` 字号，因为组件内的固定字号可能覆盖继承值。
4. 下面是设置组件内的局部 CSS 修改示例，应合并到现有规则中，保留原有颜色和其他布局属性。它只覆盖列出的选择器，其他小字需逐项检查：

   ```css
   .label {
     font-size: 16px;
     line-height: 1.4;
   }

   .desc {
     font-size: 14px;
     line-height: 1.5;
   }

   .val {
     font-size: 14px;
     min-width: 2.4em;
   }
   ```

5. 对实际的底部按钮和菜单选项设置 `font-size: 16px`、合适的行高及至少 `44px` 的最小高度。文字拥挤时，让工具栏换行或按原有交互支持横向滚动；设置行允许说明换行，并保持滑块、开关和数值可见。同步检查固定高度容器以及终端可用高度，避免底部栏变高后遮挡终端。
6. 在浏览器缩放 **100%** 下预览修改，再以手机实际视口检查设置页、底部栏、弹出菜单、输入框以及键盘展开后的布局。终端正文继续由终端字号控制，不要用全局 `* { font-size: ... !important; }` 或整体 `transform: scale(...)` 放大应用。
7. 按所选源码版本的项目说明安装依赖、执行检查并构建。先确认该版本如何将前端资源交付给 Agent；若资源嵌入二进制，需要构建包含新前端的 Agent，不能只把 CSS 文件放进安装目录。具体构建与替换命令应在核对该版本脚本和实际服务路径后确定。
8. 验收构建产物后安排部署，保留可回退的原版本。服务重启会中断当前连接，应避开关键操作。部署后重新加载页面，验证浏览器和 PWA 均取得新资源；不要通过清除全部站点数据强制刷新，以免丢失配对信息。

前端修改的恢复方式是重新部署备份版本，并按需要将浏览器缩放恢复到 100%。仅恢复主题不能撤销源码中的字号修改。

## 6. 处理终端对话中的背景色块

PocketShell 的主题与终端内开发工具的主题是两层设置。若普通 shell 文字已经清楚，但对话中的提示框、代码块、差异背景仍难读，应调整正在运行的工具。

1. 查看该工具自身的主题选项，优先尝试浅色或高对比模式。
2. 如果它提供减少颜色、关闭装饰背景或关闭动画的选项，再逐项测试。不同工具命令不同，不使用未经确认的通用命令。
3. 如果工具明确支持 `NO_COLOR`，可对单次启动测试 `NO_COLOR=1`；它不是所有工具通用的开关，也不保证移除所有背景色。不要直接写入全局 shell 配置。
4. 分别检查普通对话、代码块、选中文字、输入提示和 Git 差异。不能只看一段普通文本就认为全部配色已修复。

## 7. 验收与恢复

| 场景 | 通过标准 |
| --- | --- |
| 中文和英文对话 | 无需临时放大，静止时可辨认细笔画 |
| 深浅背景块 | 块内文字没有消失，选择文本后仍可读 |
| 设置说明与底部按钮 | 可辨认文字，按钮完整且可点击 |
| 输入与滚动 | 键盘不挡输入区，刷新速度可接受，残影可通过刷新消除 |
| 返回页面 | 锁屏或切换应用后，字号、主题与布局仍符合预期 |

建议记录最终采用的 PocketShell 字号、主题、浏览器缩放、Bigme 刷新模式，以及仍有问题的具体区域。当前推荐起点是：**字号 18 + 浅色主题 + 偏清晰的刷新模式 + 浏览器缩放 100%**，之后逐项调整。

恢复方法：切回原主题或 Cream Light，浏览器缩放恢复 100%，恢复之前记录的设备显示参数。无需重装服务。

如果这样调整后菜单仍明显偏小或模糊，按第 5.3 节修改 PocketShell 前端的界面字号，并检查辅助文字对比、按钮尺寸或字重；这些不是当前主题配置能完全处理的。本次仅补充配置与修改指南，没有修改或重新部署前端。
